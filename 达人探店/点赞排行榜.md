`Set`是无序的， `List`虽然有序，但是不唯一，查找效率也比较低

此时我们就可以选择使用`SortedSet`这个数据结构，它完美的满足了我们所有的需求：**唯一**、**有序**、**查找效率高**。

相较于Set集合，SortedList有以下不同之处：

对于Set集合我们可以使用 isMember方法判断用户是否存在，对于SortedList我们可以使用ZSCORE方法判断用户是否存在
Set集合没有提供范围查询，无法获排行榜前几名的数据，SortedList可以使用ZRANGE方法实现范围查询



# 代码
```java
@Service
public class BlogServiceImpl extends ServiceImpl<BlogMapper, Blog> implements IBlogService {

    @Resource
    private IUserService userService;

    @Resource
    private StringRedisTemplate stringRedisTemplate;

    /**
     * 根据id查询博客
     *
     * @param id
     * @return
     */
    @Override
    public Result queryBlogById(Long id) {
        // 查询博客信息
        Blog blog = this.getById(id);
        if (Objects.isNull(blog)) {
            return Result.fail("笔记不存在");
        }
        // 查询blog相关的用户信息
        queryUserByBlog(blog);
        // 判断当前用户是否点赞该博客
        isBlogLiked(blog);
        return Result.ok(blog);
    }

    /**
     * 判断当前用户是否点赞该博客
     */
    private void isBlogLiked(Blog blog) {
        UserDTO user = ThreadLocalUtls.getUser();
        if (Objects.isNull(user)){
            // 当前用户未登录，无需查询点赞
            return;
        }
        Long userId = user.getId();
        String key = BLOG_LIKED_KEY + blog.getId();
        Double score = stringRedisTemplate.opsForZSet().score(key, userId.toString());
        blog.setIsLike(Objects.nonNull(score));
    }

    /**
     * 查询热门博客
     *
     * @param current
     * @return
     */
    @Override
    public Result queryHotBlog(Integer current) {
        // 根据用户查询
        Page<Blog> page = this.query()
                .orderByDesc("liked")
                .page(new Page<>(current, SystemConstants.MAX_PAGE_SIZE));
        // 获取当前页数据
        List<Blog> records = page.getRecords();
        // 查询用户
        records.forEach(blog -> {
            this.queryUserByBlog(blog);
            this.isBlogLiked(blog);
        });
        return Result.ok(records);
    }

    /**
     * 点赞
     *
     * @param id
     * @return
     */
    @Override
    public Result likeBlog(Long id) {
        // 1、判断用户是否点赞
        Long userId = ThreadLocalUtls.getUser().getId();
        String key = BLOG_LIKED_KEY + id;
        // zscore key value
        Double score = stringRedisTemplate.opsForZSet().score(key, userId.toString());
        boolean result;
        if (score == null) {
            // 1.1 用户未点赞，点赞数+1
            result = this.update(new LambdaUpdateWrapper<Blog>()
                    .eq(Blog::getId, id)
                    .setSql("liked = liked + 1"));
            if (result) {
                // 数据库更新成功，更新缓存 zadd key value score
                stringRedisTemplate.opsForZSet().add(key, userId.toString(), System.currentTimeMillis());
            }
        } else {
            // 1.2 用户已点赞，点赞数-1
            result = this.update(new LambdaUpdateWrapper<Blog>()
                    .eq(Blog::getId, id)
                    .setSql("liked = liked - 1"));
            if (result) {
                // 数据更新成功，更新缓存 zrem key value
                stringRedisTemplate.opsForZSet().remove(key, userId.toString());
            }
        }
        return Result.ok();
    }

    /**
     * 查询所有点赞博客的用户
     *
     * @param id
     * @return
     */
    @Override
    public Result queryBlogLikes(Long id) {
        // 查询Top5的点赞用户 zrange key 0 4
        Long userId = ThreadLocalUtls.getUser().getId();
        String key = BLOG_LIKED_KEY + id;
        Set<String> top5 = stringRedisTemplate.opsForZSet().range(key, 0, 4);
        if (top5 == null || top5.isEmpty()) {
            return Result.ok(Collections.emptyList());
        }
        List<Long> ids = top5.stream().map(Long::valueOf).collect(Collectors.toList());
        List<UserDTO> userDTOList = userService
		        .list(new LambdaQueryWrapper<User>()
		        .in(User::getId, ids)
                .last("order by field (id," + idStr + ")"))
                .map(user -> BeanUtil.copyProperties(user, UserDTO.class))
                .collect(Collectors.toList());
        return Result.ok(userDTOList);
    }

    /**
     * 查询博客相关用户信息
     *
     * @param blog
     */
    private void queryUserByBlog(Blog blog) {
        Long userId = blog.getUserId();
        User user = userService.getById(userId);
        blog.setName(user.getNickName());
        blog.setIcon(user.getIcon());
    }
}

```

## 二、重点方法解析

### 1. `likeBlog()`：点赞 / 取消点赞（ZSet 版本）

```java
public Result likeBlog(Long id) {
    Long userId = ThreadLocalUtls.getUser().getId();
    String key = BLOG_LIKED_KEY + id;

    // ① 用 ZSCORE 判断是否已赞
    Double score = stringRedisTemplate.opsForZSet()
            .score(key, userId.toString());

    if (score == null) {
        // ② 未点赞 → 点赞
        
        // 先更新数据库：点赞数 +1
        boolean result = this.update(new LambdaUpdateWrapper<Blog>()
                .eq(Blog::getId, id)
                .setSql("liked = liked + 1"));
        
        if (result) {
            // ZADD：member=userId，score=当前时间戳
            stringRedisTemplate.opsForZSet()
                    .add(key, userId.toString(), System.currentTimeMillis());
        }
    } else {
        // ③ 已点赞 → 取消点赞
        
        boolean result = this.update(new LambdaUpdateWrapper<Blog>()
                .eq(Blog::getId, id)
                .setSql("liked = liked - 1"));
        
        if (result) {
            // ZREM：从 ZSet 移除
            stringRedisTemplate.opsForZSet()
                    .remove(key, userId.toString());
        }
    }
    return Result.ok();
}
```

**和 Set 版本的核心区别：**

| 操作 | Set 版本 | ZSet 版本 |
|:---|:---|:---|
| 判断是否已赞 | `SISMEMBER` | `ZSCORE` |
| 添加点赞 | `SADD key userId` | `ZADD key score userId` |
| 取消点赞 | `SREM key userId` | `ZREM key userId` |

**ZSet 的关键优势**：`add` 时多传了当前时间戳作为 score，这样点赞顺序就被记录下来了。

### 2. `queryBlogLikes()`：查询点赞排行榜 Top 5

这是本节**新增的核心功能**。

```java
public Result queryBlogLikes(Long id) {
    String key = BLOG_LIKED_KEY + id;
    
    // ① ZRANGE key 0 4：按 score 升序取前 5 个
    Set<String> top5 = stringRedisTemplate.opsForZSet()
            .range(key, 0, 4);
    
    if (top5 == null || top5.isEmpty()) {
        return Result.ok(Collections.emptyList());
    }
    
    // ② 把用户 ID 转成 List<Long>
    List<Long> ids = top5.stream()
            .map(Long::valueOf)
            .collect(Collectors.toList());
    
    // ③ 根据 ID 批量查用户，并保持 ZSet 的顺序
    List<UserDTO> userDTOList = userService.list(
            new LambdaQueryWrapper<User>()
                    .in(User::getId, ids)
                    .last("order by field (id, " + idStr + ")"))
            .stream()
            .map(user -> BeanUtil.copyProperties(user, UserDTO.class))
            .collect(Collectors.toList());
    
    return Result.ok(userDTOList);
}
```

**执行流程：**

```
ZRANGE blog:liked:{id} 0 4
    │
    ▼
拿到前 5 个 userId（按点赞时间升序）
    │
    ▼
批量查数据库：SELECT * FROM user WHERE id IN (...)
    │
    ▼
ORDER BY FIELD(id, ...) 保持 ZSet 返回的顺序
    │
    ▼
返回给前端
```

### 3. `isBlogLiked()`：判断当前用户是否已赞（ZSet 版本）

```java
private void isBlogLiked(Blog blog) {
    UserDTO user = ThreadLocalUtls.getUser();
    if (Objects.isNull(user)) {
        // 未登录，不查
        return;
    }
    Long userId = user.getId();
    String key = BLOG_LIKED_KEY + blog.getId();
    
    // ZSCORE：返回 score 则已赞，返回 null 则未赞
    Double score = stringRedisTemplate.opsForZSet()
            .score(key, userId.toString());
    
    blog.setIsLike(Objects.nonNull(score));
}
```

**关键改进**：增加了**未登录判断**。

```java
if (Objects.isNull(user)) {
    return;  // 未登录直接返回，不查 Redis
}
```

这比之前 Set 版本更严谨，避免了游客访问时 `ThreadLocalUtls.getUser()` 返回 null 导致的空指针。

## 三、数据库查询保持顺序的技巧

这是本段代码里**最容易忽略但很重要的细节**：

```java
.last("order by field (id, " + idStr + ")")
```

### 为什么需要这个？

`ZRANGE` 返回的是按**点赞时间升序**的用户 ID：

```
["1003", "1001", "1002"]   ← 1003 最早点赞
```

但 MySQL 的 `WHERE id IN (1003, 1001, 1002)` 默认返回顺序可能是：

```
[1001, 1002, 1003]   ← 数据库自己排的，顺序乱了
```

`ORDER BY FIELD(id, 1003, 1001, 1002)` 强制 MySQL 按指定的 ID 顺序返回，**保持和 ZSet 一致的排名顺序**。

## 四、关键点总结

| 重点 | 说明 |
|:---|:---|
| 数据结构 | `ZSet`，member=userId，score=时间戳 |
| 判断是否已赞 | `ZSCORE`（返回 null 表示未赞） |
| 点赞 | `ZADD key 当前时间戳 userId` |
| 取消赞 | `ZREM key userId` |
| 排行榜 Top 5 | `ZRANGE key 0 4`（score 升序 = 时间最早在前） |
| 保持顺序 | `ORDER BY FIELD(id, ...)` 防止数据库打乱顺序 |
| 未登录处理 | `isBlogLiked` 里先判空，避免空指针 |

## 五、完整数据流

```
用户点赞
    │
    ▼
ZSCORE 判断是否已赞
    │
    ├─ 未赞：
    │    UPDATE blog SET liked = liked + 1
    │    ZADD blog:liked:{id} {now} {userId}
    │
    └─ 已赞：
         UPDATE blog SET liked = liked - 1
         ZREM blog:liked:{id} {userId}

用户查看排行榜
    │
    ▼
ZRANGE blog:liked:{id} 0 4
    │
    ▼
拿到前 5 个 userId（按时间升序）
    │
    ▼
SELECT * FROM user WHERE id IN (...)
    │
    ▼

    │
    ▼

```

## 六、和 Set 版本的完整对比

| 维度 | Set 版本 | ZSet 版本（本段代码） |
|:---|:---|:---|
| 数据结构 | Set | ZSet |
| 是否有序 | ❌ 无序 | ✅ 按时间戳排序 |
| 排行榜 | ❌ 不支持 | ✅ Top 5 |
| 判断是否已赞 | `SISMEMBER` | `ZSCORE` |
| 添加点赞 | `SADD` | `ZADD key timestamp userId` |
| 取消点赞 | `SREM` | `ZREM` |
| 未登录处理 | 无 | ✅ 有判空 |

**核心升级：从“只记录谁赞了”升级为“记录谁赞了 + 什么时候赞的 + 按时间排序”。**
