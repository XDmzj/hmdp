
# 缓存概念介绍

### 一、 什么是缓存？

**缓存（Cache）** 是一种用于**快速存取数据的临时存储介质**。它的核心原理是：**用更高的成本（如内存空间）或更近的距离，换取更快的访问速度**。

#### 核心矛盾：速度差异

在计算机架构中，不同存储介质的读写速度存在数量级的差异：

- **内存（RAM）**：读写速度在 **纳秒（ns）** 级别（访问 Redis/本地内存）。
    
- **磁盘（SSD / HDD）**：读写速度在 **微秒（μs）到毫秒（ms）** 级别（访问 MySQL 等关系型数据库）。
    

当大量的并发请求直接打到数据库时，磁盘 I/O 会迅速打满，造成响应变慢甚至服务崩溃。**缓存的目的，就是将高频访问的数据存放在离 CPU 更近、速度极快的内存中，从而避免直接调用昂贵的磁盘 I/O 操作。**

### 二、 在黑马点评中，缓存有什么用？

在《黑马点评》项目中，缓存（主要基于 **Redis** 和 **本地 JVM 内存**）贯穿了几乎所有高并发场景，主要发挥了以下几大核心作用：

#### 1. 降低数据库压力，提升查询性能（读缓存）

- **场景**：店铺信息查询（`/shop/{id}`）、店铺类型列表（`/shop-type/list`）。
    
- **作用**：店铺信息是典型**读多写少**的数据。如果每次查看店铺都去查 MySQL，高并发下数据库很容易瘫痪。
    
- **做法**：优先从 Redis 读，命中直接返回；未命中再去查数据库，并将结果回写到 Redis。响应时间直接从数十毫秒降低到几毫秒。
    

#### 2. 分布式会话与状态共享（共享 Token 缓存）

- **场景**：短信验证码登录、用户登录状态维持。
    
- **作用**：替代传统单机的 `HttpSession`，解决多台 Tomcat 集群部署时的**Session 共享问题**，同时利用 TTL（过期时间）自动清除过期验证码和失效 Token。
    

#### 3. 秒杀高并发抗压与预扣减（高性能读写）

- **场景**：秒杀优惠券库存扣减（`/voucher-order/seckill/{id}`）。
    
- **作用**：如果几千人同时抢券，直接去数据库做 `UPDATE tb_seckill_voucher SET stock = stock - 1` 会产生严重的数据库行锁竞争导致超时。
    
- **做法**：将优惠券库存和一人一单信息**预热**到 Redis 中，结合 Lua 脚本在 Redis 内部完成原子性的**预扣库存和校验**。瞬间将数千 QPS 的高并发压力拦截在内存层，异步再由 MQ 或线程池慢慢写入 MySQL。
    

#### 4. 高级数据结构实现特定业务（位图 / GEO 等）

- **场景**：
    
    - 用户签到功能：使用 Redis 的 **BitMap（位图）**，只用极小的内存（几百 KB）就能记录用户一年的签到状态。
        
    - 附近商户检索：使用 Redis 的 **GEO（地理位置）** 结合 **HyperLogLog** 快速计算商家与用户的距离并排序。
        

### 三、 什么是多级缓存？

#### 1. 概念与痛点

在普通的单架构中，我们通常采用 **`应用服务 -> Redis -> MySQL`** 的结构，这叫**单级缓存（Redis 缓存）**。

但在极高并发（如双十一秒杀、热点突发新闻）下，仅依赖 Redis 可能会面临**网络带宽瓶颈**或**Redis 单核性能瓶颈（Hotkey 导致单节点打满）**。

**多级缓存（Multi-Level Cache）** 就是指在请求经过的**不同层级**上，设置多道不同介质的缓存屏障，构建一个“层层过滤”的拦截网。

#### 2. 典型的多级缓存架构流转

数据从离用户最近的地方开始拦截，层层向后：

```
客户端请求
   │
   ▼
1. 浏览器/客户端缓存 (HTTP Cache / LocalStorage)
   │ (未命中)
   ▼
2. CDN / Nginx 静态资源与 OpenResty 本地缓存 (边缘/网关级缓存)
   │ (未命中)
   ▼
3. JVM 本地内存缓存 (Caffeine / Guava Cache)
   │ (未命中)
   ▼
4. 分布式缓存 (Redis 集群)
   │ (未命中)
   ▼
5. 最终落盘数据库 (MySQL)
```

#### 3. 各层级的作用与区别

|**缓存层级**|**存储介质**|**读写速度**|**缺点 / 难点**|
|---|---|---|---|
|**Nginx / OpenResty 缓存**|Nginx 进程内存 (Lua)|极快（无需经过 Java 进程）|逻辑简单，不适合复杂业务处理。|
|**JVM 本地缓存 (Caffeine)**|Java 进程内存|最快（无网络开销，本地内存直接读）|占用 JVM 堆内存；**多节点间存在数据不一致风险**。|
|**分布式缓存 (Redis)**|独立 Redis 服务内存|极快（带一次网络 RTT 传输耗时，约 1-3ms）|存在网络开销；需要维护 Redis 高可用集群。|

#### 4. 多级缓存的核心难题：数据一致性

当 MySQL 中的数据修改了，如何保证 Nginx、Caffeine、Redis 中的缓存同步更新？

- **常规解决方案**：修改数据库后，发送 **MQ（消息队列）广播**，让所有 Java 节点的 JVM 缓存和 Redis 同时失效/更新；或者结合 Canal 监听 MySQL Binlog 异步清理缓存。

其他痛点参考[[缓存三大痛点]]

# 店铺缓存

## 使用redis实现简单的店铺信息缓存

逻辑

![[Pasted image 20260730110009.png|378]]

service层代码

```java
   /**
     * 根据id查询商铺数据
     *
     * @param id
     * @return
     */
    @Override
    public Result queryById(Long id) {
        String key = CACHE_SHOP_KEY + id;
        // 1、从Redis中查询店铺数据
        String shopJson = stringRedisTemplate.opsForValue().get(key);

        Shop shop = null;
        // 2、判断缓存是否命中
        if (StrUtil.isNotBlank(shopJson)) {
            // 2.1 缓存命中，直接返回店铺数据
            shop = JSONUtil.toBean(shopJson, Shop.class);
            return Result.ok(shop);
        }
        // 2.2 缓存未命中，从数据库中查询店铺数据
        shop = this.getById(id);

        // 4、判断数据库是否存在店铺数据
        if (Objects.isNull(shop)) {
            // 4.1 数据库中不存在，返回失败信息
            return Result.fail("店铺不存在");
        }
        // 4.2 数据库中存在，写入Redis，并返回店铺数据
        stringRedisTemplate.opsForValue().set(key, JSONUtil.toJsonStr(shop));
        return Result.ok(shop);
    }
```

```java
@Override  
public Result queryTypeList() {  
    String typeKey= RedisConstants.CACHE_TYPE_KEY;  
    //1.从redis中查询  
    Long typeListSize = stringRedisTemplate.opsForList().size(typeKey);  
    //2.redis存在数据  
    if (typeListSize!=null&&typeListSize!=0){  
        List<String> typeJsonList = stringRedisTemplate.opsForList().range(typeKey, 0, typeListSize-1);  
        List<ShopType> typeList=new ArrayList<>();  
        for (String typeJson : typeJsonList) {  
            typeList.add(JSONUtil.toBean(typeJson,ShopType.class));  
        }  
        return Result.ok(typeList);  
    }  
    //3.redis不存在数据 查询数据库  
    List<ShopType> typeList = query().orderByAsc("sort").list();  
    //4.数据库中不存在相关数据  
    if (typeList==null){  
        //数据库不存在数据  
        return Result.fail("发生错误");  
    }  
    //转换  
    List<String> typeJsonList=new ArrayList<>();  
    for (ShopType shopType : typeList) {  
        typeJsonList.add(JSONUtil.toJsonStr(shopType));  
    }  
    //5.数据库存在数据 写入redis  
    stringRedisTemplate.opsForList().rightPushAll(typeKey,typeJsonList);  
    //6.返回数据  
    return Result.ok(typeList);  
}
```

这里redis使用list来存储店铺类型信息，方便对列表项单独进行 Push/Pop 等微调更新，但是代码会多一些循环操作

如果用string，只需要读取一次



## 给店铺信息缓存添加处理数据一致性的机制
	
```java
    /**
     * 根据id查询商铺数据（查询时，重建缓存）
     *
     * @param id
     * @return
     */
    @Override
    public Result queryById(Long id) {
        String key = CACHE_SHOP_KEY + id;
        // 1、从Redis中查询店铺数据
        String shopJson = stringRedisTemplate.opsForValue().get(key);

        Shop shop = null;
        // 2、判断缓存是否命中
        if (StrUtil.isNotBlank(shopJson)) {
            // 2.1 缓存命中，直接返回店铺数据
            shop = JSONUtil.toBean(shopJson, Shop.class);
            return Result.ok(shop);
        }
        // 2.2 缓存未命中，从数据库中查询店铺数据
        shop = this.getById(id);

        // 4、判断数据库是否存在店铺数据
        if (Objects.isNull(shop)) {
            // 4.1 数据库中不存在，返回失败信息
            return Result.fail("店铺不存在");
        }
        // 4.2 数据库中存在，重建缓存，并返回店铺数据
        stringRedisTemplate.opsForValue().set(key, JSONUtil.toJsonStr(shop), CACHE_SHOP_TTL, TimeUnit.MINUTES); 加入了redis超时清理机制
        return Result.ok(shop);
    }

    /**
     * 更新商铺数据（更新时，更新数据库，删除缓存）
     *
     * @param shop
     * @return
     */
@Override  
@Transactional  
public Result update(Shop shop) {  
    Long id = shop.getId();  
    if(id==null){  
        return Result.fail("店铺id不能为空");  
    }  
    //1.更新数据库  
    updateById(shop);  
    //2.删除缓存  
    stringRedisTemplate.delete(RedisConstants.CACHE_SHOP_KEY+shop.getId());  
    return Result.ok();  
}
```
