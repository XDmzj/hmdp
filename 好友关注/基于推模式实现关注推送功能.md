## 模式选择
当前项目用户量比较小，所以这里我们选择使用推模式，延迟低、内存占比也没那么大

由于我们需要实现分页查询功能，这里我们可以选择 list 或者 SortedSet，而不能使用Set，因为Set是无需的， list是有索引的，SortedSet 是有序的，那么我们该如何选择呢？

如果我们选择 list 会存在索引漂移现象（这个在Vue中也存在），从而导致读取重复数据，所以我们不能选择使用 list

     * 保存探店笔记
     *
     * @param blog
     * @return
     */
    @Override
    public Result saveBlog(Blog blog) {
        Long userId = ThreadLocalUtls.getUser().getId();
        blog.setUserId(userId);
        // 保存探店笔记
        boolean isSuccess = this.save(blog);
        if (!isSuccess){
            return Result.fail("笔记保存失败");
        }
        // 查询笔记作者的所有粉丝
        List<Follow> follows = followService.list(new LambdaQueryWrapper<Follow>()
                .eq(Follow::getFollowUserId, userId));
        // 将笔记推送给所有的粉丝
        for (Follow follow : follows) {
            // 获取粉丝的id
            Long id = follow.getUserId();
            // 推送笔记
            String key = FEED_KEY + id;
            stringRedisTemplate.opsForZSet().add(key, blog.getId().toString(), System.currentTimeMillis());
        }
        return Result.ok(blog.getId());
    }

## 滚动分页查询

![[Pasted image 20260819140512.png]]
思路

我们选择使用**滚动分页**，我们使用`SortedSet`，如果使用排名和使用角标是一样的，但是`SortedSet`可以按照`Score`排序（Score默认按照时间戳生成，所以是固定的），每次我们可以选择比之前Score较小的，这样就能够实现滚动排序，从而防止出现问题![[Pasted image 20260819131736.png]]





### 滚动分页查询中的 ZSet 命令参数

---

#### 一、背景：滚动分页要解决什么问题？

**传统分页**（`LIMIT offset, size`）在动态 Feed 流中有问题：当用户刷到第 2 页时，如果新数据不断插入列表头部，会导致**重复看到同一条数据**或**漏掉数据**。

**滚动分页的思路**：不用页码，而是用**上一次查询到的最后一条记录的 score（或 ID）作为游标**，下一次从这个游标之后继续查。这样即使头部有新数据插入，也不会影响已读位置。

---

#### 二、Scroll 查询的核心命令：`ZREVRANGEBYSCORE`

**Redis 命令格式**：

```bash
ZREVRANGEBYSCORE key max min LIMIT offset count
```

**参数说明**：

| 参数 | 含义 |
|:---|:---|
| `key` | ZSet 的 Key |
| `max` | score 最大值（查询上限） |
| `min` | score 最小值（查询下限） |
| `LIMIT offset count` | 跳过 offset 条，取 count 条 |

**注意是 `max min`，不是 `min max`**——因为是**倒序**（REV），从大到小查。

---

#### 三、为什么用 `ZREVRANGEBYSCORE` 而不是 `ZRANGE`？

Feed 流展示的是**最新发布的内容排前面**。

如果 score 是时间戳：

| 笔记 | 发布时间戳 |
|:---|:---|
| m1 | 1692000000000 |
| m2 | 1692000001000 |
| m3 | 1692000002000 |
| m4 | 1692000003000 |

-   最新的（时间戳最大）应该排第一
-   `ZRANGE` 是升序，从小到大 → 最旧的排前
-   `ZREVRANGEBYSCORE` 是降序，从大到小 → 最新的排前

---

#### 四、滚动分页具体怎么用？

#### 场景：查询某个用户收件箱的 Feed 流

**Key**：
```
feed:user:1001
```

**ZSet 内容**：

| member（笔记ID） | score（时间戳） |
|:---|:---|
| m1 | 1692000000000 |
| m2 | 1692000001000 |
| m3 | 1692000002000 |
| m4 | 1692000003000 |
| m5 | 1692000004000 |

##### 第一页（查最新 3 条）：

```bash
ZREVRANGEBYSCORE feed:user:1001 +inf -inf LIMIT 0 3
```

-   `max = +inf`：从头开始（最新）
-   `min = -inf`：没有下限
-   `LIMIT 0 3`：跳过 0 条，取 3 条

**结果**：

```
[m5, m4, m3]   （最新 3 条）
```

**记录游标**：这次查到的最后一条是 `m3`，它的 score 是 `1692000002000`。

##### 第二页（继续往下翻）：

```bash
ZREVRANGEBYSCORE feed:user:1001 1692000002000 -inf LIMIT 1 3
```

-   `max = 1692000002000`：从上次最后一条的 score 开始
-   `LIMIT 1 3`：跳过 1 条（因为 m3 上次已经看过了），再取 3 条

**结果**：

```
[m2, m1]   （剩余 2 条）
```

---
#### 五、完整滚动分页流程

假设一屏 3 条：

```
第 1 次请求：max = 当前时间戳, offset = 0
   ↓
查 [m5, m4, m3]
   ↓
返回给前端，同时返回 m3 的时间戳作为下一次的 max
   ↓
第 2 次请求：max = m3 的时间戳, offset = 1
   ↓
跳过 m3（因为 offset=1），查 [m2, m1]
   ↓
返回给前端，同时返回 m1 的时间戳
   ↓
第 3 次请求：max = m1 的时间戳, offset = 1
   ↓
没有数据了，返回空
```



### 黑马点评中的offset

在黑马点评里，**offset 是动态计算的**，前端每次会传两个参数：

1. `lastId`（上次查询的最后一条的 score，即时间戳）
    
2. `offset`（下次查询要跳过的条数）
    

**offset 怎么算？**

当第一次查询后，如果最后一条的 score 在结果集中出现了多次，需要把 offset 设为"这个 score 在本次结果中出现了多少次"。

**举个实际例子**（一屏 3 条）：

ZSet：
~~~text
m5(1692000002000)
m4(1692000001000)
m3(1692000000000)
m2(1692000000000)
m1(1692000000000)
~~~
第 1 页：`ZREVRANGEBYSCORE key +inf -inf LIMIT 0 3`

结果：`[m5, m4, m3]`

- `lastId = 1692000000000`（m3 的 score）
    
- 这个 score 在结果中出现了 1 次（m3）
    
- 前端设置 `offset = 1`
    

第 2 页：`ZREVRANGEBYSCORE key 1692000000000 -inf LIMIT 1 3`

- 跳过 m3，取 m2、m1
    

**如果第一次查询的最后两条 score 相同**：

第 1 页结果：`[m5, m4, m3]`，其中 m3 和 m4 的 score 都是 `1692000000000`

- 此时 `lastId = 1692000000000`
    
- 这个 score 在结果中出现了 2 次（m4、m3）
    
- 前端设置 `offset = 2`
    

第 2 页：`ZREVRANGEBYSCORE key 1692000000000 -inf LIMIT 2 3`

- 跳过 m4 和 m3，取 m2、m1、以及更早的
    

总结

|问题|答案|
|---|---|
|score 重复吗？|可以重复，ZSet 内部按 member 字典序排序|
|会导致什么问题？|同 score 多条时，简单 offset 会漏或重复|
|怎么解决？|动态计算 offset，让 offset = 上次结果中最后一个 score 出现的次数|
|前端传什么？|`lastId`（游标 score）+ `offset`（跳过条数）|
|后端怎么做？|用 `ZREVRANGEBYSCORE` 配合动态 offset 查下一页|

实现

```java
    /**
     * 关注推送页面的笔记分页
     *
     * @param max
     * @param offset
     * @return
     */
    @Override
    public Result queryBlogOfFollow(Long max, Integer offset) {
        // 1、查询收件箱
        Long userId = ThreadLocalUtls.getUser().getId();
        String key = FEED_KEY + userId;
        // ZREVRANGEBYSCORE key Max Min LIMIT offset count
        Set<ZSetOperations.TypedTuple<String>> typedTuples = stringRedisTemplate.opsForZSet()
                .reverseRangeByScoreWithScores(key, 0, max, offset, 2);
        // 2、判断收件箱中是否有数据
        if (typedTuples == null || typedTuples.isEmpty()) {
            return Result.ok();
        }

        // 3、收件箱中有数据，则解析数据: blogId、minTime（时间戳）、offset
        List<Long> ids = new ArrayList<>(typedTuples.size());
        long minTime = 0; // 记录当前最小值
        int os = 1; // 偏移量offset，用来计数
        for (ZSetOperations.TypedTuple<String> tuple : typedTuples) { // 5 4 4 2 2
            // 获取id
            ids.add(Long.valueOf(tuple.getValue()));
            // 获取分数（时间戳）
            long time = tuple.getScore().longValue();
            if (time == minTime) {
                // 当前时间等于最小时间，偏移量+1
                os++;
            } else {
                // 当前时间不等于最小时间，重置
                minTime = time;
                os = 1;
            }
        }

        // 4、根据id查询blog（使用in查询的数据是默认按照id升序排序的，这里需要使用我们自己指定的顺序排序）
        String idStr = StrUtil.join(",", ids);
        List<Blog> blogs = this.list(new LambdaQueryWrapper<Blog>().in(Blog::getId, ids)
                .last("ORDER BY FIELD(id," + idStr + ")"));
        // 设置blog相关的用户数据，是否被点赞等属性值
        for (Blog blog : blogs) {
            // 查询blog有关的用户
            queryUserByBlog(blog);
            // 查询blog是否被点赞
            isBlogLiked(blog);
        }

        // 5、封装并返回
        ScrollResult scrollResult = new ScrollResult();
        scrollResult.setList(blogs);
        scrollResult.setOffset(os);
        scrollResult.setMinTime(minTime);

        return Result.ok(scrollResult);
    }

```
