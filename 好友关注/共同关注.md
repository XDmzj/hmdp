# 代码

```java
@Service
public class FollowServiceImpl extends ServiceImpl<FollowMapper, Follow> implements IFollowService {

    @Resource
    private StringRedisTemplate stringRedisTemplate;

    @Resource
    private IUserService userService;

    /**
     * 关注用户
     *
     * @param followUserId 关注用户的id
     * @param isFollow     是否已关注
     * @return
     */
    @Override
    public Result follow(Long followUserId, Boolean isFollow) {
        Long userId = ThreadLocalUtls.getUser().getId();
        String key = FOLLOW_KEY + userId;
        if (isFollow) {
            // 用户为关注，则关注
            Follow follow = new Follow();
            follow.setUserId(userId);
            follow.setFollowUserId(followUserId);
            boolean isSuccess = this.save(follow);
            if (isSuccess) {
                // 用户关注信息保存成功，把关注的用户id放入Redis的Set集合中，
                stringRedisTemplate.opsForSet().add(key, followUserId.toString());
            }
        } else {
            // 用户已关注，删除关注信息
            boolean isSuccess = this.remove(new LambdaQueryWrapper<Follow>()
                    .eq(Follow::getUserId, userId)
                    .eq(Follow::getFollowUserId, followUserId));
            if (isSuccess) {
                stringRedisTemplate.opsForSet().remove(key, followUserId.toString());
            }
        }
        return Result.ok();
    }

    /**
     * 是否关注用户
     *
     * @param followUserId 关注用户的id
     * @return
     */
    @Override
    public Result isFollow(Long followUserId) {
        Long userId = ThreadLocalUtls.getUser().getId();
        int count = this.count(new LambdaQueryWrapper<Follow>()
                .eq(Follow::getUserId, userId)
                .eq(Follow::getFollowUserId, followUserId));
        return Result.ok(count > 0);
    }

    /**
     * 查询共同关注
     *
     * @param id
     * @return
     */
    @Override
    public Result followCommons(Long id) {
        Long userId = ThreadLocalUtls.getUser().getId();
        String key1 = FOLLOW_KEY + userId;
        String key2 = FOLLOW_KEY + id;
        // 查询当前用户与目标用户的共同关注对象
        Set<String> intersect = stringRedisTemplate.opsForSet().intersect(key1, key2);
        if (Objects.isNull(intersect) || intersect.isEmpty()) {
            return Result.ok(Collections.emptyList());
        }
        List<Long> ids = intersect.stream().map(Long::valueOf).collect(Collectors.toList());
        // 查询共同关注的用户信息
        List<UserDTO> userDTOList = userService.listByIds(ids).stream()
                .map(user -> BeanUtil.copyProperties(user, UserDTO.class))
                .collect(Collectors.toList());
        return Result.ok(userDTOList);
    }
}

```


## 共同关注功能实现思路

**核心思想**：用 Redis 的 `Set` 存储每个用户关注的用户 ID，然后利用 **`SINTER`（交集）** 命令，一次性求出两个用户共同关注的人。

---

### 一、数据结构设计

**每个用户都有一个“关注集合”**：

| Key | Value（Set） |
|:---|:---|
| `follows:1001` | `{"1002", "1003", "1005"}` |
| `follows:1002` | `{"1003", "1004"}` |

比如，用户 1001 关注了 1002、1003、1005。
用户 1002 关注了 1003、1004。

**共同关注**：就是这两个 Set 的交集，即 `{"1003"}`。

---

### 二、数据库 vs Redis 实现对比

**传统数据库做法**（用 SQL）：

```sql
SELECT * FROM tb_follow 
WHERE user_id = 1001 
  AND follow_user_id IN (
      SELECT follow_user_id FROM tb_follow WHERE user_id = 1002
  )
```

每次查询都要扫描表，关注关系多了会慢。

**Redis 做法**：

```bash
SINTER follows:1001 follows:1002
```

两个 Set 直接求交集，在内存中完成，速度快很多。

---

### 三、代码逐步解析

```java
public Result followCommons(Long id) {
    Long userId = ThreadLocalUtls.getUser().getId();
    
    // 1. 当前用户关注集合的 Key
    String key1 = FOLLOW_KEY + userId;   // 如 follows:1001
    
    // 2. 目标用户关注集合的 Key
    String key2 = FOLLOW_KEY + id;        // 如 follows:1002
    
    // 3. 核心：SINTER 求交集
    Set<String> intersect = stringRedisTemplate.opsForSet()
            .intersect(key1, key2);
    
    // 4. 没有共同关注
    if (Objects.isNull(intersect) || intersect.isEmpty()) {
        return Result.ok(Collections.emptyList());
    }
    
    // 5. String 类型的用户 ID 转成 List<Long>
    List<Long> ids = intersect.stream()
            .map(Long::valueOf)
            .collect(Collectors.toList());
    
    // 6. 批量查询共同关注的用户信息
    List<UserDTO> userDTOList = userService.listByIds(ids).stream()
            .map(user -> BeanUtil.copyProperties(user, UserDTO.class))
            .collect(Collectors.toList());
    
    return Result.ok(userDTOList);
}
```

### 四、执行流程图

```
用户 1001 查看和 1002 的共同关注
    │
    ▼
Redis 中两个 Set：
   follows:1001 = {"1003", "1005", "1007"}
   follows:1002 = {"1003", "1006"}
    │
    ▼
SINTER follows:1001 follows:1002
    │
    ▼
结果：{"1003"}
    │
    ▼
转成 List<Long>: [1003]
    │
    ▼
数据库批量查用户信息：
   SELECT * FROM tb_user WHERE id IN (1003)
    │
    ▼
返回给前端
```

### 五、为什么 Redis 存在这里？

**因为关注数据在“关注功能”时已经写进了 Redis**：

```java
// follow 方法中：
if (isFollow) {
    this.save(follow);                    // 数据库保存关注关系
    stringRedisTemplate.opsForSet()
        .add(FOLLOW_KEY + userId, followUserId.toString());  // Redis 同步保存
} else {
    this.remove(...);                     // 数据库删除
    stringRedisTemplate.opsForSet()
        .remove(FOLLOW_KEY + userId, followUserId.toString()); // Redis 同步删除
}
```

这样 Redis 里就完整维护了每个用户的关注集合，查询共同关注时直接用 `SINTER` 就能快速求出，而不需要去数据库做多表关联。

### 六、关键点和总结

| 问题 | 答案 |
|:---|:---|
| 核心命令 | `SINTER`（Set 交集） |
| Key 设计 | `follows:{userId}`，每个用户一个 Set |
| 存什么 | 该用户关注的所有用户 ID |
| 共同关注怎么算 | 两个用户的 Set 求交集 |
| 为什么快 | Redis 内存中直接求交集，避免数据库复杂查询 |
| 交集结果后做什么 | 转成 `List<Long>`，批量查数据库拿用户详情 |

**一句话总结：关注时把“我关注了谁”用 Redis Set 存起来，查共同关注时用 `SINTER` 求两个 Set 的交集，再根据交集 ID 查用户详情。**
