2）在ShopServiceImpl中编写查询代码


```java
@Override
    public Result queryShopByType(Integer typeId, Integer current, Double x, Double y) {
        // 1.判断是否需要根据坐标查询
        if (x == null || y == null) {
            // 不需要坐标查询，按数据库查询
            Page<Shop> page = query()
                    .eq("type_id", typeId)
                    .page(new Page<>(current, SystemConstants.DEFAULT_PAGE_SIZE));
            // 返回数据
            return Result.ok(page.getRecords());
        }

        // 2.计算分页参数
        int from = (current - 1) * SystemConstants.DEFAULT_PAGE_SIZE;
        int end = current * SystemConstants.DEFAULT_PAGE_SIZE;

        // 3.查询redis、按照距离排序、分页。结果：shopId、distance
        String key = SHOP_GEO_KEY + typeId;
        GeoResults<RedisGeoCommands.GeoLocation<String>> results = stringRedisTemplate.opsForGeo() // GEOSEARCH key BYLONLAT x y BYRADIUS 10 WITHDISTANCE
                .search(
                        key,
                        GeoReference.fromCoordinate(x, y),
                        new Distance(5000),
                        RedisGeoCommands.GeoSearchCommandArgs.newGeoSearchArgs().includeDistance().limit(end)
                );
        // 4.解析出id
        if (results == null) {
            return Result.ok(Collections.emptyList());
        }
        List<GeoResult<RedisGeoCommands.GeoLocation<String>>> list = results.getContent();
        if (list.size() <= from) {
            // 没有下一页了，结束
            return Result.ok(Collections.emptyList());
        }
        // 4.1.截取 from ~ end的部分
        List<Long> ids = new ArrayList<>(list.size());
        Map<String, Distance> distanceMap = new HashMap<>(list.size());
        list.stream().skip(from).forEach(result -> {
            // 4.2.获取店铺id
            String shopIdStr = result.getContent().getName();
            ids.add(Long.valueOf(shopIdStr));
            // 4.3.获取距离
            Distance distance = result.getDistance();
            distanceMap.put(shopIdStr, distance);
        });
        // 5.根据id查询Shop
        String idStr = StrUtil.join(",", ids);
        List<Shop> shops = query().in("id", ids).last("ORDER BY FIELD(id," + idStr + ")").list();
        for (Shop shop : shops) {
            shop.setDistance(distanceMap.get(shop.getId().toString()).getValue());
        }
        // 6.返回
        return Result.ok(shops);
    }

```


## 解析
这段代码是**按距离搜索附近商铺并分页返回**的完整实现，核心利用 Redis GEO 做地理位置搜索，然后从数据库查详情。

---

### 一、整体执行流程

```
用户请求：typeId（商铺类型）、current（页码）、x y（用户坐标）
    │
    ├─ 没有坐标？ → 直接按数据库分页查
    │
    └─ 有坐标？
         │
         ├─ 算出需要跳过多少条（from）和取到多少条（end）
         │
         ├─ GEOSEARCH 从 Redis 查附近所有商铺，按距离升序，取前 end 条
         │
         ├─ 用 skip(from) 截取当前页要的部分
         │
         ├─ 拿店铺 ID 去数据库查详情，并保持距离顺序
         │
         ├─ 把距离回填到 Shop 对象
         │
         └─ 返回
```

---

### 二、逐段解析

#### 1. 判断是否需要坐标查询

```java
if (x == null || y == null) {
    // 无坐标 → 按传统数据库分页查
    Page<Shop> page = query()
            .eq("type_id", typeId)
            .page(new Page<>(current, SystemConstants.DEFAULT_PAGE_SIZE));
    return Result.ok(page.getRecords());
}
```

- 前端没传坐标 → 不做地理搜索
- 直接数据库 `WHERE type_id = ?` 分页查

---

#### 2. 计算分页参数

```java
int from = (current - 1) * SystemConstants.DEFAULT_PAGE_SIZE;
int end = current * SystemConstants.DEFAULT_PAGE_SIZE;
```

假设一页 10 条：

| current | from | end |
|:---|:---|:---|
| 1 | 0 | 10 |
| 2 | 10 | 20 |
| 3 | 20 | 30 |

**from**：当前页要跳过的条数  
**end**：当前页要取到的位置

---

#### 3. Redis GEO 搜索

```java
GeoResults<RedisGeoCommands.GeoLocation<String>> results = 
    stringRedisTemplate.opsForGeo().search(
        key,
        GeoReference.fromCoordinate(x, y),      // 用户坐标圆心
        new Distance(5000),                      // 半径 5000 米
        RedisGeoCommands.GeoSearchCommandArgs
            .newGeoSearchArgs()
            .includeDistance()                    // 返回距离
            .limit(end)                           // 只取前 end 条
    );
```

**对应 Redis 命令**：

```bash
GEOSEARCH shop:geo:1 FROMLONLAT x y BYRADIUS 5000 m ASC COUNT end WITHDIST
```

- 搜索半径 5 公里内的所有商铺
- 按距离升序排序（GEO 默认升序）
- 只取前 `end` 条

**为什么只取前 end 条？** 因为分页只需要前 `end` 条数据，后面的不需要。

---

#### 4. 解析出商铺 ID 和距离

```java
if (results == null) {
    return Result.ok(Collections.emptyList());
}

List<GeoResult<RedisGeoCommands.GeoLocation<String>>> list = results.getContent();

if (list.size() <= from) {
    // 没有下一页了
    return Result.ok(Collections.emptyList());
}
```

- 结果为空直接返回
- 如果总数还没到 `from`，说明当前页已经没数据了

```java
List<Long> ids = new ArrayList<>(list.size());
Map<String, Distance> distanceMap = new HashMap<>(list.size());

list.stream().skip(from).forEach(result -> {
    String shopIdStr = result.getContent().getName();
    ids.add(Long.valueOf(shopIdStr));
    Distance distance = result.getDistance();
    distanceMap.put(shopIdStr, distance);
});
```

**重点：`skip(from)`**

- GEO 返回了前 `end` 条
- `skip(from)` 跳过前面页的数据
- 只留下当前页需要的部分

**举例**（一页 10 条，current=2）：

- from=10，end=20
- GEO 返回了前 20 条
- `skip(10)` → 留下第 11 到第 20 条

---

#### 5. 根据 ID 查数据库并保持顺序

```java
String idStr = StrUtil.join(",", ids);
List<Shop> shops = query()
        .in("id", ids)
        .last("ORDER BY FIELD(id," + idStr + ")")
        .list();
```

- `StrUtil.join(",", ids)`：把 `[5,3,8]` 变成 `"5,3,8"`
- `ORDER BY FIELD(id,5,3,8)`：强制 MySQL 按 GEO 返回的距离顺序排

**为什么需要？** 数据库 `IN` 查询默认按主键升序，会打乱距离排序。

---

#### 6. 回填距离

```java
for (Shop shop : shops) {
    shop.setDistance(distanceMap.get(shop.getId().toString()).getValue());
}
```

- `distanceMap` 在第四步已经存储了每个商铺 ID 对应的距离
- 这里把距离值填入 `Shop` 对象的 `distance` 字段
- 前端可以直接显示"距离 3.2 km"

### 三、完整流程图

```
用户搜索餐厅，坐标 (116.39, 39.91)，第 2 页，一页 10 条
    │
    ▼
from = 10, end = 20
    │
    ▼
GEOSEARCH shop:geo:1 FROMLONLAT 116.39 39.91 BYRADIUS 5000 m LIMIT 20
    │
    ▼
返回 20 条，按距离升序
    │
    ▼
skip(10) → 留下第 11~20 条
    │
    ▼
拿到 10 个商铺 ID + 它们的距离
    │
    ▼
SELECT * FROM shop WHERE id IN (...) ORDER BY FIELD(id, ...)
    │
    ▼
回填 distance 到每个 Shop 对象
    │
    ▼
返回给前端
```

### 四、关键点总结

| 问题 | 答案 |
|:---|:---|
| 无坐标怎么办？ | 直接数据库分页查，不走 GEO |
| 为什么用 `limit(end)`？ | 分页只需要前 end 条，多余的不取 |
| 为什么用 `skip(from)`？ | 跳过前面页的数据，只留当前页 |
| 为什么用 `ORDER BY FIELD`？ | 保持 GEO 距离排序，不让数据库乱序 |
| 距离怎么给前端？ | 存在 `distanceMap`，查完数据库后回填到 Shop 对象 |
| GEO 返回什么？ | 商铺 ID + 距离 |

---

### 五、和基础版 GEO 搜索的区别

| 维度 | 基础版 | 这个版本 |
|:---|:---|:---|
| 分页 | 无 | 有（from/end） |
| 距离存储 | 直接返回 | 用 Map 存，回填到对象 |
| 数据库顺序 | 可能乱 | `ORDER BY FIELD` 保持距离顺序 |
| 无坐标情况 | 无处理 | 走数据库查询 |
| 下一页判断 | 无 | `list.size() <= from` 提前返回 |

**核心设计：GEO 负责“谁在我附近”和“距离多少”，数据库负责“商铺详情”，通过 ID 关联两者。**
